# 嵌入式设备版本号完整规范

> 适用场景：智慧农业嵌入式设备，485 通信、物联网上报、设备固件、配置协议。
> 本文件为规范全量内容，可直接作为协议文档的素材，也可用于评审与决策。

---

## 一、版本号要求（四类）

### 1、固件版本号（FirmwareVersion）

**格式：`V主版本.次版本.修订号[.编译号]`**

> 示例：`V1.4.2` / `2.1.5.240831`（上报时必须带 `V` 前缀，如 `V1.4.2`）

- **主版本(Major)**：重大架构变更、协议不兼容升级。※改动此号代表旧上位机不能兼容
- **次版本(Minor)**：新增功能，协议向下兼容
- **修订号(Patch)**：bug 修复，无新增功能
- **编译号(Build，可选)**：编译日期/流水线编号，用于工厂定位版本

**约束要求**

1. 格式 `Vx.y.z`，V 大写，数字为十进制，禁止字母（除前缀 V）
2. 协议上报字符串示例：`"FirmwareVersion":"V1.4.2"`
3. 禁止：`v1.0`（小写 v）、`1.0.0-beta`（带 beta 后缀）。设备端尽量只用数字版本；测试版本内部可以带后缀，对外协议去掉

### 2、硬件版本号（HardwareVersion）

标识 PCB 硬件、板子版本。

- 格式：`HW_V主.次`，示例：`HW_V1.2`
- HW 前缀，主.次，硬件改版升级时递增
- 上报示例：`"HardwareVersion":"HW_V1.3"`

### 3、通信协议版本号（ProtocolVersion）

非常关键，485/上报接口用来做兼容性判断。

- 格式：`A.B`
- A：协议大版本，变更后上下机必须同步升级，不兼容旧设备
- B：协议小版本，新增字段，向下兼容
- 示例：`"ProtocolVersion":"2.0"`

### 4、配置文件版本号（ConfigVersion）

用于 TOML/XML 配置，配置结构发生变化时递增，用来做配置迁移。

- 格式：正整数，示例：`ConfigVersion = 12`（纯整数，简单高效）

## 二、协议文档里可直接粘贴的【版本号要求】段落

> ### 版本号要求
> 1. 固件版本号格式：`V<主>.<次>.<修订>`，如 `V1.3.5`；V 字符大写，各段为十进制非负整数。主版本变更代表固件接口不兼容；次版本代表新增功能；修订版本代表缺陷修复。
> 2. 硬件版本格式：`HW_V<主>.<次>`，硬件 PCB 改版时更新。
> 3. 通信协议版本格式：`<主>.<次>`。协议主版本变更，设备与平台必须成对升级，不向下兼容；次版本增加字段，保持向后兼容。
> 4. 所有版本号通过串口/报文上报时，使用字符串类型。
> 5. 禁止使用 `alpha/beta/rc` 等后缀用于正式生产版本；测试样机可保留后缀，量产版本只保留数字。

## 三、示例

### C 语言结构体示例

```c
typedef struct
{
    char FirmwareVersion[16];   // "V1.4.2"
    char HardwareVersion[16];   // "HW_V1.2"
    char ProtocolVersion[16];   // "2.1"
}DeviceVersionInfo;
```

### JSON 上报示例

```json
{
    "FirmwareVersion": "V1.4.2",
    "HardwareVersion": "HW_V1.2",
    "ProtocolVersion": "2.1"
}
```

### 配置文件示例（TOML）

```toml
ConfigVersion = 12          # 配置文件结构版本，结构变更时递增并触发迁移
ProductModel = "AGRI-485-A1"
```

## 四、版本变更决策表

| 变更内容 | 需要升的版本号 | 是否要求三方联动升级 |
|---|---|---|
| 新增命令码/上报字段（旧端忽略未知字段即可） | ProtocolVersion.B、FirmwareVersion.次 | 否（向后兼容） |
| 修改/删除已有字段、改变帧格式 | ProtocolVersion.A、FirmwareVersion.主 | 是（必须成对升级） |
| 新增业务功能 | FirmwareVersion.次 | 否 |
| 修复 bug、优化性能 | FirmwareVersion.修 | 否 |
| PCB 改版、换料、引脚变更 | HardwareVersion | 视引脚兼容性而定 |
| 配置文件字段/结构变化 | ConfigVersion | 是（需迁移逻辑） |

## 五、兼容性矩阵（设备 / 上位机 / 平台）

| 设备协议 A | 上位机协议 A | 结果 |
|---|---|---|
| 相同 | 相同 | 完全兼容 |
| 相同 | 更高（A 相同，B 更高） | 兼容，设备忽略未知新增字段 |
| 更高 | 相同 | 兼容，上位机忽略未知新增字段 |
| 主版本不同（A 不同） | — | **不兼容，禁止直连，必须成对升级** |

> 兼容性判断以 ProtocolVersion 为准，与 FirmwareVersion 无关。

## 六、校验规则（正则参考）

```text
固件版本:  ^V\d+\.\d+\.\d+(\.\d+)?$
硬件版本:  ^HW_V\d+\.\d+$
协议版本:  ^\d+\.\d+$
配置版本:  ^[1-9]\d*$        （正整数）
```

> 校验只做格式检查，兼容性判断由协议主版本号决定。
