# 版本变更影响分析模板

> 每次修改版本号（或触发版本号变更的改动）时，按本模板向用户输出影响说明。
> 目的：让用户一眼看清"改完会发生什么、要不要联动升级、有没有迁移成本"。

## 模板

```markdown
## 版本变更影响说明

**变更内容**：描述改了什么（如：新增读取设备型号命令 0x05，FirmwareVersion V1.3.0 → V1.4.0）

### 1. 兼容性影响
- 旧上位机/平台能否解析新报文：□ 能（向后兼容） □ 不能（需同步升级）
- 原因（一句话）：

### 2. 升级联动
- 需要联动升级的对象：□ 设备固件 □ 上位机 □ 云平台 □ 全部
- 建议升级顺序：
- 若只升级一方会发生什么：

### 3. 数据迁移
- 是否需要配置迁移：□ 否 □ 是（ConfigVersion 变化）
- 迁移策略（旧配置如何处理）：

### 4. 测试范围
- 受影响接口/命令码：
- 受影响上报字段：
- 建议回归项：

### 5. 本次建议
- 建议版本号变更：FirmwareVersion：__ / HardwareVersion：__ / ProtocolVersion：__ / ConfigVersion：__
- 一句话总结（给决策者）：
```

## 示例（协议新增字段，向后兼容）

```markdown
## 版本变更影响说明

**变更内容**：上报 JSON 新增"电量百分比"字段 battery:0-100，ProtocolVersion 2.0 → 2.1

### 1. 兼容性影响
- 旧平台能否解析：能。旧平台忽略未知字段，设备仍按 2.0 帧格式发送（字段追加在末尾）
- 原因：次版本变更，向后兼容

### 2. 升级联动
- 需联动对象：仅设备固件（平台可选升级以展示新字段）
- 升级顺序：先平台侧兼容旧格式，再分批升级设备
- 只升级设备：平台照常运行，只是看不到电量字段

### 3. 数据迁移
- 不需要，协议字段变更与配置无关

### 4. 测试范围
- 485 上报报文解析、JSON schema 校验、电量字段边界值（0/100/越界）

### 5. 本次建议
- ProtocolVersion：2.1，FirmwareVersion 次版本递增
- 一句话：安全的小版本升级，设备可单独先上
```

## 示例（协议不兼容变更）

```markdown
## 版本变更影响说明

**变更内容**：485 帧头从 0xAA55 改为 0xEB90，命令码重排，ProtocolVersion 2.1 → 3.0

### 1. 兼容性影响
- 旧上位机：不能解析，帧头校验直接丢弃 → 通信全断
- 原因：主版本变更，不向下兼容

### 2. 升级联动
- 需联动：设备 + 上位机/平台，缺一不可
- 升级顺序：先上位机/平台支持双帧头过渡期，再逐台升级设备
- 只升级设备：现场全部掉线（禁止）

### 3. 数据迁移
- 不需要配置迁移，但需在 NVM 标记旧固件可回退

### 4. 测试范围
- 全量命令码回归、485 组网轮询、升级后自动重连、旧固件回退路径

### 5. 本次建议
- ProtocolVersion：3.0（FirmwareVersion 同步升主版本）
- 一句话：高危变更，必须制定灰度升级方案，禁止直接批量下发
```
