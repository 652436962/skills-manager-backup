# 嵌入式设备版本号规范

## 用途

统一嵌入式设备（智慧农业、485 通信、物联网上报、配置协议）中固件/硬件/协议/配置四类版本号的定义、格式与变更规则，保证设备端、上位机、云平台三方对版本兼容性的判断一致，避免因版本号混乱导致现场无法升级、报文解析失败、配置错乱。

## 核心规范（四类版本号）

| 类型 | 格式 | 示例 | 变更语义 |
|---|---|---|---|
| FirmwareVersion 固件版本号 | `V主.次.修订[.编译号]` | `V1.4.2` | 主=架构重构/协议不兼容；次=新增功能(兼容)；修=bug 修复；编译号可选，用于工厂定位 |
| HardwareVersion 硬件版本号 | `HW_V主.次` | `HW_V1.2` | PCB 硬件改版/引脚变化时递增 |
| ProtocolVersion 通信协议版本号 | `A.B` | `2.0` | A 变=设备与平台必须成对升级、不兼容旧设备；B 变=新增字段、向后兼容 |
| ConfigVersion 配置文件版本号 | 正整数 | `12` | 配置结构变化时递增，用于触发配置迁移 |

> 完整规范、可粘贴文档段落、C 结构体/JSON 示例、变更决策规则见 `references/versioning-spec.md`。

## 工作流

### 1. 修改版本号前，先给出变更影响说明

任何一次版本号修改，都必须先向用户说明"这么改会产生什么影响"，至少覆盖四个方面：

- **兼容性**：旧上位机/云平台是否还能解析新报文（协议主版本变更 = 完全不可兼容）
- **升级联动**：是否需要设备 + 上位机 + 平台成对升级，升级顺序是什么
- **数据迁移**：配置结构变化时是否需要 ConfigVersion 迁移，旧配置如何处理
- **测试范围**：受影响的命令码、上报字段、485 从机地址等

影响分析模板见 `references/change-impacts.md`，直接在回复中按模板输出。

### 2. 判断该升哪个版本号

按变更类型对照：

- 协议字段增/删/改、命令码变化、帧格式变化 → 升 **ProtocolVersion**
- 固件新增功能、修复 bug、优化 → 升 **FirmwareVersion**
- PCB 改版、器件更换、引脚定义变化 → 升 **HardwareVersion**
- 配置文件结构/字段变化 → 升 **ConfigVersion**（并准备迁移逻辑）
- 涉及多类变更时，各版本号分别递增，互不替代

### 3. 输出规范时，直接使用可粘贴段落

协议文档需要"版本号要求"章节时，直接引用 `references/versioning-spec.md` 中的【协议文档里可直接粘贴的版本号要求段落】，保持各文档间口径一致。

### 4. 维护版本文件（CHANGELOG）

每个程序/项目在根目录维护 `CHANGELOG.md`，逐版本记录修改内容并关联 git 提交：

- 条目格式：`## [Vx.y.z] - 日期 (git短哈希)`，如 `## [V1.3.2] - 2026-08-27 (265e20c)`
- 日常改动记入顶部 "Unreleased" 区；发版时 commit 取哈希 → 落正式条目 → 打同名 git tag
- 版本号变化必须在 CHANGELOG 有对应条目，禁止无记录改版本
- 格式与工作流详见 `references/changelog-spec.md`

### 5. 检查禁用项

- 禁止小写 `v`（应为大写 `V`）
- 禁止 `beta/alpha/rc` 等后缀用于量产/对外协议版本（测试样机内部可带，对外上报去掉）
- 禁止版本号中出现非十进制字符
- 禁止协议不兼容变更却不升主版本号
- 禁止将版本号字符串当数值直接比较（如 `"V1.10"` 与 `"V1.9"` 的字典序陷阱）
- 禁止版本号变更但 CHANGELOG 无对应记录

## 补充建议（经验补充）

- 版本号在 485/串口/上报中一律使用**字符串类型**传输，禁止转浮点后比较。
- 设备端提供固定命令码的"读取版本信息"命令，一次返回四类版本号，便于产线与现场定位。
- 在 NVM/Flash 中保存出厂版本与历次升级记录，现场回退、售后定位问题时可直接读取。
- 多设备 485 组网时，平台侧应能按从机地址分别读取每台设备的版本，并做版本差异汇总。
- 固件升级包建议携带"目标固件版本 + 最低可升级来源版本"，在设备端做升级前校验，防止跨大版本直接升级导致配置不兼容。
- 配置文件迁移建议保留旧版本解析路径：读取到旧 ConfigVersion 时按迁移链逐级升级，而不是直接拒绝。

## 约束（不要针对性编程）

本 skill 只提供**通用规范与流程**，不针对任何特定项目、特定硬件、特定上位机编写实现代码或专有协议细节。需要落地的报文格式、命令码、存储结构由使用者按项目实际填充。
